# 05 — 校验层分析与最终结论

## 实验

| 包 | 内容 | 结果 |
|---|---|---|
| 官方原始 `.dat` | 3.21 | ✅ 刷入 |
| 重打包（官方内容，版本 3.22/3.24） | 未改内容 | ✅ 刷入，相机正常启动并报新版本 |
| 重打包 + 改 `beeplist.txt`（版本 3.23） | 改了 13 字节 | ❌ `Firmware update error: Invalid data` |

## 结论

相机对固件内容有一层**超出 CRC32 的完整性/签名校验**：

- `part_image.sum` 的 CRC32 已按修改后重算，仍被拒；
- 官方内容重打包（tar 结构、fdat 头、版本号都变）能通过，说明不是容器格式问题；
- 只有内容字节变化时被拒 → 判定为 **Sony 签名/内容摘要校验**。

因此：

1. 改 AF 提示音、改 daemon、改任何文件 → 需要伪造 Sony 签名，**私钥不可得**；
2. 本项目的改机路线到此为止；
3. 可用的安全增强仍然是 PMCA 应用层（OpenMemories 等），不涉及固件修改。

## 给后来者

如果你有 Sony 的签名工具或能拿到未签名固件的加载路径，欢迎补充；否则不建议在这条路上继续投入。
